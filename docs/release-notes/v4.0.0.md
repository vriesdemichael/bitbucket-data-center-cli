bb v4.0.0 is the release where the output contract stops moving, the safety
rails start working, and a number of commands begin doing what they always said
they did.

Most of it came from one exercise: every command was run against a real
Bitbucket Data Center instead of a test double. That found defects the unit
suite had been agreeing with for months — a pull request update that silently
removed every reviewer, three transitions that could not succeed without a flag
nobody knew to pass, `--limit` flags that did nothing on seven commands. Those
are fixed, and the suite that missed them has been replaced by one that talks to
a server.

### If you script bb, read this part

Four changes will break automation, and all four are worth the break.

**Machine output is camelCase, and the envelope is smaller.** Every `--json`
field now matches the name Bitbucket uses. `meta.contract` and the contract
version are gone: neither ever varied, so both were ceremony that scripts had to
parse and nobody could use. The binary version is reported instead.

**Secrets no longer go on the command line.** `--token` and `--password` are
retired. Pass credentials through the environment or on stdin, where they stay
out of shell history, process listings and CI logs.

**Destructive commands ask first**, and never read stdin unless you told them
to. A command that would prompt in a pipeline now fails with a clear message
rather than blocking forever on an empty pipe.

**Exit codes mean what ADR-011 says they mean.** Twenty-two errors bb raises
itself were unclassified; a forgotten required flag was reported as an internal
defect; an unreachable host disagreed with itself between a dry run and a real
run. If your scripts branch on exit codes, they will now see the right ones —
which for some failures is a different code than before.

### Paging actually pages

`--limit` was accepted and ignored on seven commands: branch restriction list,
commit compare, pr commits, pr files, repo browse tree, branch model inspect,
and the pull request comment listings. Others paged to exhaustion and returned
everything regardless of what you asked for, and `bulk` planned only the first
hundred repositories in a project — quietly, which is the worst way to plan a
bulk change.

Every service now walks pages the same way, and a cap is a cap.

### Pull requests

The four defects that started this release:

- `pr update` replaced the whole pull request object, and Bitbucket reads an
  absent `reviewers` array as "remove them all". Updating a title emptied the
  reviewer list. Reviewers are preserved, and `--reviewers` changes them on
  purpose.
- `pr decline`, `merge` and `reopen` sent an unset version, which the server
  refuses. All three now resolve the current version, so they work without
  `--version`.
- `pr create` pre-checked write access on the target repository, which made the
  standard fork-to-upstream contribution impossible for anyone without upstream
  write. It checks read access, and `--from-repo` names the fork.
- CODEOWNERS reviewer-group entries were sent as usernames and refused. bb no
  longer parses CODEOWNERS at all — Bitbucket resolves it, and bb asks. Its
  answer is the one the web interface shows, which is not always the one our
  parser produced.

### Smaller, sharper

Auto-merge, rebase and fork synchronisation each had a request that could not
succeed against a real server. Dry-run previews state their confidence from a
tier rather than from the author's optimism. Retries no longer replay POST and
PATCH after a lost response, which could double a mutation. A rebase with
nothing to do is a success, not an internal error.

### Upgrading

There is no compatibility shim. The output contract changed once, deliberately,
and pinning v3 remains available if you are not ready — v4 will not quietly
change it again.
