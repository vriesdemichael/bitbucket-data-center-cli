bb v4.1.0 adds `bb doctor` for configuration problems and closes most of the remaining gap with `gh` for pull requests and repositories. It also makes failures say what actually happened: whether a request that never got an answer may have been applied, whether a listing was cut short, and which file or policy refused a command.

It is a minor release with no breaking changes. Several fixes restore behaviour that ADRs and the v4.0.0 notes had already promised, and the ones a script or pipeline can notice are in the checklist below.

### Highlights

* **`bb doctor` ([ADR-086](https://vriesdemichael.github.io/bitbucket-data-center-cli/latest/adr/086-bb-doctor-reports-the-configuration-without-loading-it/), [#597](https://github.com/vriesdemichael/bitbucket-data-center-cli/issues/597)):** Checks the stored, workspace and system configuration files and reports every problem at once:
  * schema violations, with their key and line;
  * keys a file never reads, such as `require_keyring` in a user's own file;
  * where each effective setting comes from;
  * whether a required OS keyring answers.

  It needs no Bitbucket host, makes no network call, and exits 1 when there is anything to fix.
* **Closer to `gh` ([ADR-050](https://vriesdemichael.github.io/bitbucket-data-center-cli/latest/adr/050-shallow-aliases-for-deep-command-paths/), [#575](https://github.com/vriesdemichael/bitbucket-data-center-cli/issues/575)):**
  * `bb pr view`, `bb pr edit` and `bb pr close` resolve, and `bb pr checks` shows a pull request's build statuses.
  * `bb pr ready` marks a draft ready for review without asking for its version, and `--undo` turns it back into a draft ([#602](https://github.com/vriesdemichael/bitbucket-data-center-cli/issues/602)).
  * `bb repo get`, also spelled `bb repo view`, describes a repository and prints its README ([#605](https://github.com/vriesdemichael/bitbucket-data-center-cli/issues/605)).
* **Failures that say what happened ([ADR-011](https://vriesdemichael.github.io/bitbucket-data-center-cli/latest/adr/011-error-taxonomy-and-cli-exit-contract/), [#574](https://github.com/vriesdemichael/bitbucket-data-center-cli/issues/574)):**
  * A change whose response never came back exits `13` (`unknown_outcome`), because it may have been applied.
  * A rejected TLS certificate or a DNS failure exits `1` (`permanent`) instead of inviting a retry.
  * A `401` that refuses a known user is `authorization`, not `authentication`.
  * Upstream response bodies are summarised and redacted before they reach a message, and `error.details` carries `upstreamStatus` and `upstreamException`.
* **Truncation you can see ([#573](https://github.com/vriesdemichael/bitbucket-data-center-cli/issues/573)):** Every listing that takes `--limit` reports `meta.limitReached`, and MCP results and text output say so too.
* **Release integrity:**
  * Every release archive carries its own SPDX SBOM, generated from the binary inside it and attested against the archive.
  * `bb update` fetches release mirrors over `https` unless plain HTTP is explicitly allowed ([ADR-059](https://vriesdemichael.github.io/bitbucket-data-center-cli/latest/adr/059-enterprise-update-controls-and-release-mirrors/)).
  * GitHub Actions are pinned to commits, and the unit suite runs natively on Windows and macOS.

### Before you upgrade: scripts and CI

1. **Deleting a branch, a tag or a webhook asks for confirmation ([ADR-073](https://vriesdemichael.github.io/bitbucket-data-center-cli/latest/adr/073-interactive-when-a-person-is-there-explicit-when-not/)).**
   * In a pipeline, pass `--yes`.
   * `--yes` does not cover a repository inferred from the git remote. Name it with `--repo PROJECT/slug`, so running in the wrong checkout cannot delete from the wrong repository.
2. **A subcommand that a command group does not know exits `2`.** It used to print the group's help and exit `0`, which put prose on stdout under `--json`. The help now goes to stderr.
3. **Exit codes a retry wrapper should know.**
   * `13` means the request was sent and may have been applied, so check before sending it again.
   * Certificate and DNS failures are `1`, not `10`.
4. **`bb update` refuses a plain-HTTP release mirror**, and any download or redirect that points at one.
   * `bb update --allow-http` or `BB_ALLOW_HTTP_UPDATE=1` permits it.
   * `allow_http_update: false` in system policy refuses it for every user.
5. **`--dry-run` no longer changes the local machine either.** `bb auth logout` and `bb auth setup-git` used to apply their change under `--dry-run`.
6. **A configuration file bb cannot read is an error, not an empty file.**
   * Commands name the file and stop, instead of reporting that you are not logged in.
   * `bb auth login` no longer rewrites a file it could not read, which used to remove every other host.
   * `BB_DISABLE_STORED_CONFIG=1` no longer reads the stored file at all.
7. **`bb bulk` is deprecated ([ADR-084](https://vriesdemichael.github.io/bitbucket-data-center-cli/latest/adr/084-a-removed-flag-warns-for-one-major/)).**
   * It warns once per invocation on stderr, so `--json` output stays clean, and it is removed in v5.0.0.
   * Permissions, webhooks and default tasks set at project level already apply to every repository in the project. For anything else, loop over `bb repo list`.
8. **The release SBOM is per archive.**
   * `sbom.spdx.json` is no longer published; download `bb_<os>_<arch>.spdx.json` for the archive you install.
   * The `.deb` and `.rpm` are attested with the SBOM of the `_noupdate` archive.
